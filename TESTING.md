# Testing — glyphcull-runtime-js

Status: Phase 0 (foundations). The pyramid below is the target for Phase 3; every slice
lands with its subsystem.

## 1. Principles

- Tests are deterministic: no wall-clock (injected clock), no `Math.random`, no network,
  no real timers.
- Malformed-input tests assert typed errors, never thrown exceptions on internal paths.
- Golden artifacts (packages, layout records, draw lists, reference images) are committed;
  regeneration only via checked-in scripts with reviewed diffs.
- Browser-only features (WebGL, Canvas) are tested through a thin adapter interface so
  logic tests run in Node; true rendering validation runs in the browser harness
  (glyphcull-demo) and in CI via Playwright.

## 2. Layers

### Unit

- **format/**: every reader validation rule from SPEC.md §1.6; truncation corpus (every
  proper prefix of a golden package errors); CRC-32 known-answer vectors; compression
  round-trip; decode-size limits; SEAL verification pass/fail.
- **document/**: chunk graph invariants (tree consistency, dense ordinals, depth), style
  resolution defaults, content reference resolution.
- **lifecycle/**: transition table exhaustively tested; every guard tested both ways;
  transition log correctness; invalid-transition rejection; injected-clock cooling periods.
- **visibility/**: culling decisions against synthetic geometry (margin, semantic flags,
  direction of travel); culling never mutates materialization state (boundary assertion).
- **materialize/**: priority ordering (deterministic), budget exhaustion → yield, eviction
  order (cooling + LRU), no starvation of visible chunks.
- **layout/**: word-boundary tables (UAX #29 sample vectors), KP break quality on known
  texts, block layout golden fixtures, table span layout, image aspect ratios.
- **glyphs/**: cache budget enforcement, key collisions, eviction coupling with lifecycle.
- **render/**: draw list construction (batching, z-order, determinism — double-build byte
  equality), MSDF reconstruction math (unit-tested against analytic coverage), DPR
  scaling.
- **selection/**: hit testing at boundaries (before/after glyph boxes), range merging,
  copy extraction policy (paragraph breaks, table cells → tabs, rows → newlines), empty and
  full-document selections.
- **api/**: the six functions' contracts; destroyed-handle errors; double-destroy idempotent
  errors; concurrent Document isolation.

### Integration

- load → scroll → paint cycle over committed golden packages; visible set + draw list
  compared against committed fixtures.
- select → copy over mixed content (headings, lists, tables, images, code).
- Resize (scroll with new viewport) invalidates layout records and re-materializes.
- Canvas 2D and WebGL renderers produce outputs within tolerance of the reference
  rasterizer (browser harness, Playwright in CI).

### Property (fast-check)

- `decode(encode(roundtrip))` style: reader over writer-produced bytes round-trips.
- Lifecycle: random valid transition sequences never violate guards or reach undefined
  states (model-based testing with a reference state machine).
- Draw list: same inputs ⇒ identical serialized draw list (determinism).
- Reader: arbitrary bytes never throw (catch-all in property test).

### Stress

- Large documents (100k+ chunks), deep viewport jumps (full-document scroll), rapid
  scroll oscillation, selection across the whole document, simultaneous Documents.
  Assert bounded time per frame and bounded memory (see PERFORMANCE.md).

### Memory regression

- Node with `--expose-gc`: load/paint/scroll/destroy cycles; assert retained heap growth
  below committed baselines across N cycles (e.g., < 5% per cycle after warmup).
- Cache budget enforcement measured in bytes.

### Performance regression

- Benchmark suite (vitest bench) with committed baselines: load, first paint latency,
  sustained scroll frame time, materialization throughput (chunks/s), memory. CI compares
  ratios; absolute numbers are reported.

### Rendering validation

- Browser harness paints golden packages and compares pixels to reference images
  (committed, generated by the compiler's reference rasterizer) with a tolerance policy
  (mean abs ≤ 1/64, coverage-aware; documented exceptions for extreme magnification).

### Package validation

- `load()` rejects packages that fail SPEC.md reader rules or document validation with
  typed errors; every rejection has a test.

## 3. Tooling

- Vitest (unit/integration/property via fast-check), Playwright (browser rendering + perf),
  `tsc --strict` + eslint in CI, Node `--expose-gc` memory harness.
- Test helpers: fixture loader shared via a testkit module; injected clock; fake GPU
  adapter for draw-list-only tests.

## 4. CI

- fmt/lint → typecheck → unit+integration+property → memory harness → bench smoke →
  browser rendering validation (Playwright) → doc build.
